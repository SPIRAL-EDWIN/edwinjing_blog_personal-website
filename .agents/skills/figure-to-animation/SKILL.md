# Figure to animation

## Rights gate

Identify the exact figure, paper version, creator, license and intended audience before making a public adaptation; record the evidence and decision in `docs/figure-licenses.md` or the project equivalent. Animation, recoloring, and a redraw following the original composition count as adaptations for this workflow. CC BY, CC0 and public domain may be used with the required attribution; CC BY-SA additionally requires compliance with share-alike. For CC BY-NC ask the user whether the intended use is noncommercial before publishing. For CC BY-NC-ND, all-rights-reserved or unclear rights, publish no adaptation; offer a citation and link, or create an original composition explaining the underlying idea if requested. Attribution alone does not permit prohibited adaptations. When in doubt ask. This is a safeguard, not legal advice.

Private training material and all derivatives must remain outside the static source and deployment output in an ignored directory. Verify the production artifact, not just the source path. Never use a private replica as a homepage asset. Record ownership of original work too.

## Workflow

1. Examine the source, its caption and surrounding explanation. Separate observed elements from guesses; preserve uncertain relationships as unresolved instead of inventing facts. For original work, check the source notes.
2. Describe elements in a FigureSpec using `references/figure-spec.schema.json`: named layers, nodes, edges, highlights, callouts, ordered steps and reading order. Give every node integer `col` and `row` coordinates. Flow proceeds only rightward and downward: every edge's target must have `col >= source.col` and `row >= source.row`. Run `scripts/validate_spec.py SPEC.json` as a required build check; backward edges fail validation. This checks structure and references, not scientific correctness. If the source relationship cannot be expressed faithfully under that flow rule, describe the constraint instead of misrepresenting it.
3. Render a static end state first using vector edges and readable text. Compare against the source when a faithful recreation is authorized; for original work compare against the underlying facts, not the source's composition. Confirm shapes, direction, hierarchy, labels, contrast and legibility at target sizes.
4. Measure node bounds after layout and on `ResizeObserver` changes; compute connectors from source right/bottom edge midpoints to target left/top edge midpoints. Keep connectors beneath opaque cards and terminate at their edges; draw stroke source-to-target, showing the correctly oriented arrowhead only when the stroke reaches it. Use orthogonal bends when needed. Do not measure on every animation frame. Reuse the same geometry for compact previews.
5. Map reading order into a timeline with exactly three element states: hidden (opacity 0, visibility hidden), upcoming (opacity 0.35, no blur), and shown (opacity 1). Previously shown elements remain shown. Keep node geometry fixed between steps; entrance offsets must finish before the next step, at most 12px, and emphasis scale at most 1.03. Use a fixed-height cross-fading step caption and a static figure caption. Keep one meaningful change per step.
6. Pin only the content-sized figure card, not an empty viewport container. Center it while pinned; target at most 70svh, about 55–70vh scroll per step, scrub 0.4–0.6 and short ~0.25s boundary snaps. Map timeline progress to the full pin length so the final step releases immediately, without an idle tail. These numbers are starting points; adjust when required for legibility or content. No pin on narrow screens or reduced motion. Use an accessible static end state without JS and with reduced motion, keyboard-operable controls, descriptive caption and text equivalents. Avoid motion-dependent meaning.
7. Record the whole scroll and capture 0/25/50/75/100% states with `scripts/capture_frames.cjs` (requires a project-installed Playwright and browser). Review rendered frames, not just source. See `references/qa.md` for review and failure modes. Check browser support and lifecycle teardown. Document actual observations, not inferred results.

When the brief calls for a play-once figure, keep a per-figure seen flag in memory that survives instant navigation and resets on a hard reload; use session persistence only when requested. Make first-pass reveal progress forward-only. On completion or when the reader leaves the figure, mark it seen, expose the complete static state, remove its trigger and pin spacer, and compensate the scroll position in the same frame so a stable landmark does not move. Keep unseen figures eligible for their first play. Respect static mobile and reduced-motion paths, and test anchor jumps, browser navigation and reload separately.

For icon morphs, preserve the original full glyph footprint and optical center, including handles or other extending parts. Use one coordinate system, compensate scaling so stroke width stays constant, and end at the intended final scale and color. Verify before/after rendered bounds rather than comparing only individual paths.
