让模糊沿边缘淡出

把下面的色块和文字滚到导航背后。靠近顶端的内容模糊更强，向下逐渐恢复清晰；这层玻璃本身不拦截点击。

02 / STRUCTURE

内容有层次，布局有比例

宽屏采用正文与插画两列，平板收紧间距，手机切成单列。学习的是网格与内容顺序，插画不使用原站人物照片。

容器最大宽度 1120px，内边距随屏幕调整。窄屏插画固定为 200 × 250px，正文自然铺满可用宽度。

为什么用原生 details？

把次要解释折叠起来，读者需要时再展开。浏览器直接提供键盘操作和展开语义，禁用 JavaScript 也可使用。

这里的加号随 open 属性变为减号，只需 CSS，内容仍由 HTML 承载。

应该从源码中学什么？

对照页面确认组件边界，再追踪结构、样式和事件。先理解“为什么这样写”，然后使用自己的内容与视觉素材。

03 / INTERACTION

少量事件，明确反馈

滚动时，导航下划线会跟随当前章节。窄屏打开菜单后，可以按 Escape 关闭，再回到菜单按钮。

01

原生锚点

链接保留真实的 #章节。浏览器负责跳转与历史记录；脚本只计算当前位置，更新选中状态。

02

移动导航

860px 以下折叠成菜单。展开状态同步到按钮的 aria-expanded，点击章节后自动收起。

03

一次入场

章节进入视口时轻轻显现一次。减少动态效果设置会关闭位移和顺滑滚动；无脚本也能阅读全部内容。

滚动测量通过 requestAnimationFrame 合并；每个章节只在首次出现时触发入场。
